# MB07–16 controls

The user requests executable multiplication controls and their verification,
not a completion ledger. The original unpublished sources and raw receipts were
lost in workspace cleanup. This is a new reconstruction; old hashes and results
are not evidence for these files.

## Domains and effects

Inputs are positive stored lengths and unsigned 32-bit least-significant-first
limbs; outputs contain every input-length-sum word including high zeroes.
`integer_value(list[int]) → int` and independent expected products are exact.
`require(bool, str) → None` raises on failure, including under optimization.
Every measured product is checked outside the arithmetic interval. Process,
file, compiler, clock and foreign-library actions are explicit effects. Reports
bind source, input, executable, compiler, mode, architecture and raw samples.

Current shared ai-ci instructions require Ithon `.pi` checked through its actual
frontend for new Python-family programs. This selects Ithon rather than an
invented Idriç process/runtime interface. Existing corpus, provider and acceptance
Python modules remain named foreign migration debt; new controls do not add `.py`.
The inherited CPython substrate inside Ithon is its implementation boundary.
No Idriç build or acceptance is claimed. The concrete Idriç gap is a qualified
bounded process/selector/clock interface; a future port must reproduce the
hanging-child refusal and exact limb/product checks before replacing this path.

Typed lists, integers, strings and bytes carry the control data. Foreign
subprocess/path/CSV/argparse return values cross explicit typed extraction points.
The frontend checks each new module before execution. JSON is retained only for
the existing campaign/FP receipt interfaces.
