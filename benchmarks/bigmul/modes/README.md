## Measurement limits

The C workload consumes exact pregenerated input bytes. Schoolbook output and
input snapshots are prepared outside timing, while Ithon independently checks
every full output afterward. Dispatch and the opaque callback remain inside
the interval. Counted builds add a call counter; matched uninstrumented builds
compile it out and label the raw zero call field NOT_MEASURED. Every
uninstrumented workload digest has a counted counterpart. Neither is an
accepted actual-candidate speed result. The C pool is capped at 1024 requests, 2048 stored words
per operand and a configured memory budget of at most 16 MiB; the drivers use
8 MiB including conservative provider scratch reservation. Corpus generation
and receipt storage use host memory outside that C allocation budget.

Hot/rotating runs record two explicit warmup calls before bounded calibration,
and validate all warmup and calibration identities and cap/target flags.
Calibration retains its largest completed batch when the remaining call budget
cannot fit another batch of that size. With a 4096-call limit, an unmet target
therefore retains 2048 repetitions after 4095 total calibration calls, instead
of replacing that sample with the single leftover call. Deterministic fake-clock
controls cover this limit and small irregular limits. A cap hit can leave unused
calls and does not mean the target duration was reached. Earlier receipts through
`6d4b035` preserve the old behavior and are superseded for timing interpretation.
Clock-pair and volatile-callback control paths preserve 20 observations per
build and repetition size separately. No measured overhead is subtracted.
Fresh GMP timing includes import/allocation/kernel/export/free; reused native
timing includes the kernel callback only, with preparation and export outside.
Three randomized configuration blocks retain these different cost boundaries.
Generic equal-valued multiplication and specialized GMP square now cover the
full derived equal-value medium set across the stored-length grid, with their
own hashes and operation labels.
First-touch and eviction modes skip calibration and measure exactly one call.
Allocation counters reset before that measured call. A new malloc allocation
may reuse pages; it does not prove untouched OS pages or cold caches. Eviction
touches are timed separately and count one byte per 64-byte stride. No system
cache drop, privileged counter request or machine-wide change is made.
Mixed batch wall spans include validation and output formatting. Closed-loop
service times are not open-loop queue latency. No p99 claim is made.
The separate `mixed-throughput` mode puts one clock pair around the provider
calls in each arithmetic batch. Pregeneration, output prefill, full validation
and output formatting occur outside that interval. Provider dispatch and fresh
provider-owned adaptation/allocation remain inside. Response rows reference
the shared batch sample; sum `arithmetic_batches` once, never once per row.
Counted coverage and uninstrumented throughput use identical workload digests.
Individual-request p50/p90 use linear interpolation at `(sample_count-1)*p`.
The process delay is part of service time; queue time remains NOT_MEASURED.
Process failures preserve partial stdout/stderr and cannot enter a successful
throughput summary.

The separate `rotating-pool` mode measures one whole-pool batch per trial,
with enough calls to visit every request. It checks all poisoned outputs after
timing. Its rows reference one shared sample per trial, not individual request
latencies. MB09's deterministic `MB09-derived-pool-v1` family has unique 128-word
operand pairs and new case hashes; it never replaces the pinned MB03 corpus.
Working-set targets use operand payload bytes around observed cpu0 Data/Unified
cache sizes. Duplicated input snapshots, output storage and provider scratch
remain separately identified. The driver caps the operand payload at 1 MiB and
1024 pairs within its 8 MiB C budget. Larger boundaries are NOT_RUN_RESOURCE_LIMIT.
A new output malloc lifetime is counted outside the arithmetic interval; it
does not establish untouched OS pages. The retained-buffer mutant exercises
that distinction.

Memory tracking covers requested provider payload, including GMP adapter arrays,
but cannot see GMP internal allocations or allocator headers. Preparation may
leave live native storage across calls; cleanup must end at zero. Linux
`RUSAGE_SELF.ru_maxrss` is recorded in KiB and normalized to bytes, separately
from tracked heap. The fresh process still includes corpus, oracle and I/O;
its high-water mark is not a provider-only peak.

MB12 pairs uninstrumented complete-adapter samples only. Normalizations use the
fixed balanced stored-length corpus mixture, not mathematical bit length.
Crossover means the first ascending median speedup crossing on that finite
grid; the same resampled process blocks span all sizes. Censored resamples
prevent a finite interval. None of this establishes a sustained winner or an
asymptotic exponent.

The binary endpoint caps both output streams and bounds its initial request
below the local pipe envelope. A selector deadline covers the first read and
subsequent collection; failures kill/reap the child. Launch-to-first-result
ends when a complete frame is observed by the collector, so scheduling and
buffering remain part of that measurement. Binary output flushes each frame;
the inherited hex endpoint uses C stdio pipe buffering. Independent validation
is outside both clocks. Echo results form a separate distribution; no median
subtraction is presented as an exact cost decomposition.

The added counted-limb text protocol is `na nb left right` followed by newline,
with unsigned lower-case hexadecimal or decimal digits. It preserves stored limb counts
even for leading-zero inputs. Hex results use `8*(na+nb)` digits; decimal results
use `10*(na+nb)` digits. Arithmetic and zero echo therefore have identical
request bytes and output lengths within a representation. Each result is
flushed. This is a separate identity from the inherited minimal-hex endpoint.
GMP 6.3.0 performs text/binary conversion only; the named schoolbook/Karatsuba
provider performs the multiplication. The conversion follows the official
[import/export](https://gmplib.org/manual/Integer-Import-and-Export) and
[string-buffer](https://gmplib.org/manual/Converting-Integers) contracts.
Phase clocks exist only in the dedicated instrumented build. Library allocations
may occur during import/export as well as the explicit allocation phase.
Process startup and the fixed line buffer are outside the per-request phase
totals. Raw input/stdout/stderr bytes and exit status survive refusal, timeout
and post-output child failure. No phase or echo subtraction creates a claimed
uninstrumented kernel time.

`--parser-sanitizers-only` runs the text framing/conversion cases under ASan and
UBSan, including stored-width overflow, embedded NUL, bounded input length,
mid-stream refusal and the 1024-request cap. A separately wrapped C payload
lane checks actual error cleanup and refuses a retained-allocation mutant;
GMP internal allocations remain outside that counter. LeakSanitizer must also
observe the unwrapped leak mutant. The hosted workflow requires that lane.
An explicitly requested `--allow-unavailable-lsan` local run may retain an
observed LeakSanitizer process-inspection failure as NOT_AVAILABLE and continue
only the address/undefined-behavior and owned-payload controls. It never reports
LeakSanitizer PASS and is not used by hosted CI.

When MB12 writes a successful JSON receipt, it also writes the same basename
with `.md`. The readable report identifies its source and input receipt digest,
states the ratio direction and block assumptions, shows all three finite-size
normalizations, and retains censored crossover results. Rounded display values
are not substituted for raw observations.

The native driver records allowed CPU lists and available cgroup/sysfs facts
without changing affinity. It never infers bare-metal execution or exclusive
resources from those names. An isolated child PATH contains the verified
compiler, Git and launcher plumbing but no bc; required-bc mode must produce
its actual refusal receipt. The actual default MB16 gate must also refuse.

The workflow's deliberately absent upload input is a separate negative control
with `if-no-files-found: error` and an expected failure outcome. Checked Ithon
verifies that outcome and the absent input; hosted action logs must identify
the failure cause before claiming the missing-file experiment ran. Local
success/absent-outcome fixtures must fail the guard. This is distinct from the
final real receipt upload, whose artifact metadata must be checked separately.
The existing Actions `run` interface only launches checked Ithon; no shell
validation program is added. These controls do not qualify ICK or constitute
independent AICI acceptance.
