## Replaying the implemented slices

Select the verified absolute Ithon entrypoint using `ITHON` when invoking the
existing MB21 dispatcher. Direct Ithon invocations take a `.pi` entrypoint and
`--output` receipt path. Use `PYTHONOPTIMIZE=1` to test the Ithon host substrate
under optimization; Ithon still checks every source before executing it.
Set `ITHON_CHECK_RECEIPT` to a writable JSONL path to retain actual frontend
source/lowered hashes. Its parent directory must exist before invocation.
MB12 consumes the matching MB07 report via `--input`.
MB16 without `--controls-only` exits 2 with `BLOCKED`; the option qualifies only
synthetic gate fixtures and does not admit an actual candidate.

FP envelopes and stage receipts identify local host diagnostics. Kitchen/Ike
production execution and independent AICI acceptance have not been performed.
The existing native workflow qualifies a pinned Ithon frontend, then executes
the available campaign controls. It requires bc after installing it and uploads
all receipts even if a later test fails. Artifact names include run, attempt and
runner. Existing full-readiness mode still exits nonzero.

## Measurement limits

The C workload consumes exact pregenerated input bytes. Schoolbook output and
input snapshots are prepared outside timing, while Ithon independently checks
every full output afterward. Dispatch and callback-count instrumentation remain
inside the kernel interval: these are diagnostic controls, not uninstrumented
provider-speed results. The C pool is capped at 1024 requests, 2048 stored words
per operand and a configured memory budget of at most 16 MiB; the drivers use
8 MiB including conservative provider scratch reservation. Corpus generation
and receipt storage use host memory outside that C allocation budget.

Hot calibration has bounded calls/time and records cap flags separately.
First-touch and eviction modes skip calibration and measure exactly one call.
Allocation counters reset before that measured call. A new malloc allocation
may reuse pages; it does not prove untouched OS pages or cold caches. Eviction
touches are timed separately and count one byte per 64-byte stride. No system
cache drop, privileged counter request or machine-wide change is made.
Mixed batch wall spans include validation and output formatting. Closed-loop
service times are not open-loop queue latency. No p99 claim is made.

The binary endpoint caps both output streams and bounds its initial request
below the local pipe envelope. A selector deadline covers the first read and
subsequent collection; failures kill/reap the child. Launch-to-first-result
ends when a complete frame is observed by the collector, so scheduling and
buffering remain part of that measurement. Binary output flushes each frame;
the inherited hex endpoint uses C stdio pipe buffering. Independent validation
is outside both clocks. Echo results form a separate distribution; no median
subtraction is presented as an exact cost decomposition.
